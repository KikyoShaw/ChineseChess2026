# 弈 · 中国象棋

一款基于 **Tauri 2 + Vue 3 + TypeScript** 的独立桌面象棋游戏，提供离线人机、本地双人和局域网对弈。Rust 管理规则、搜索、计时和网络，Vue 呈现木质棋盘与中文交互。

## 开发运行

Windows 环境需要：

- Node.js 20 LTS 或更新版本及 npm。
- Rust stable，使用 MSVC 工具链。
- Visual Studio 2022 Build Tools 的“使用 C++ 的桌面开发”及 Windows SDK。
- Microsoft Edge WebView2 Runtime。

在项目目录打开终端：

```powershell
npm install
npm run tauri dev
```

`npm run tauri dev` 同时启动 Vite 和 Rust 后端。完整对弈需要通过 Tauri 桌面窗口运行；`npm run dev` 仅提供前端资源服务。

生成 Windows NSIS 安装包：

```powershell
npm run tauri build
```

安装包位于 `src-tauri/target/release/bundle/nsis/`。首次构建需要下载 npm、Cargo 依赖及 Tauri 打包工具。本次交付未安装依赖，未执行构建、类型检查、测试或应用启动。

## 对弈模式

- **人机**：默认玩家执红、红方先行，每步 30 秒。可设置阵营、先手和三档难度；AI 使用 Alpha-Beta 剪枝与迭代加深，上限为 2/3/4 层，思考预算约 200/650/1500 毫秒，并受当前剩余步时限制。
- **本地双人**：在同一块棋盘轮流操作。悔棋退回两步，不足两步时退一步。
- **人机悔棋**：撤回玩家最近一手及电脑回复；电脑尚在思考时仅撤回玩家一手。电脑先行且玩家尚未落子时不可悔棋。
- **每步计时**：落子后为下一方重置时限，超时判负。设为 `0` 表示不限时；Rust 单调时钟负责最终裁定。

点击本方棋子后选择目标位置。支持棋盘翻转、合法落点、最近一步标记、将军提示、落子动画和音效开关。翻转只影响观看方向。

## 开始与暂停

打开应用、新建对局、修改对局设置后重开或导入局面后，棋局均处于“待开始”状态。点击工具栏的 **开始** 才会开始倒计时、允许落子；电脑先手也会等待开始。

对弈中点击 **暂停**，会冻结本步剩余时间、禁止落子，并取消正在进行的电脑搜索。点击 **继续**，从暂停前的剩余时间恢复；轮到电脑时重新安排搜索，不会补满当前步时。不限时对局同样需要开始，也可以暂停。

暂停时可以保存局面、翻转棋盘或悔棋。悔棋保留原有运行/暂停状态，并为退回后的那一步重置完整时限。对局结束后开始/暂停按钮不可用，需要重新开局。

中文棋谱按红黑双列展示，并记录每步本地时间。棋谱用于记录，不提供历史局面回放。

将死、困毙均判无合法着法的一方负。支持认输与和棋；本地及人机模式求和经确认后生效。相同布局及行棋方第三次出现时自动和棋，采用娱乐规则，不包含赛事级长将、长捉裁决。

## 局域网

1. 两台电脑接入同一局域网，使用相同版本的客户端。本机也可以打开两个客户端，使用 `127.0.0.1` 对弈。
2. 房主在联机窗口创建房间，设置自己的阵营、先手、每步时限和端口，默认端口 `8000`。
3. 对方输入房主的局域网 IP 与端口加入。Windows 可用 `ipconfig` 查看本机 IPv4 地址。
4. 若防火墙提示，请允许客户端在当前专用网络通信。每个房间容纳一名对手。

连接成功后，双方先等待**房主点击开始**。开始、暂停和继续统一由房主控制，访客同步显示状态。等待对手、待开始和暂停期间不计时，也不能落子。

房主验证落子与超时。悔棋、求和、重开需要对方同意；请求 30 秒未答复或棋局发生变化时失效。对局运行时等待答复仍继续计时；暂停时保持冻结，协商请求仍须在 30 秒内答复。协商期间开始/暂停/继续按钮不可用；同意重开后回到待开始。认输直接生效。

断线时保留棋盘和当前剩余时间，已开始的棋局转为暂停。可离开房间，将当前局面转为本地双人；未开始的等待开始，已开始的等待点击继续。访客从该局面重新记录棋谱，房主保留原棋谱。再次联机需先离开当前房间。首版不自动重连。

网络使用版本化 JSON、四字节大端长度前缀和棋谱分片同步，单帧最多 64 KiB，完整同步最多 8 MiB；当前协议版本为 2，联机双方需使用支持相同协议的客户端，无需账号或云服务。

## 保存与设置

“打开 / 保存”使用系统文件对话框，默认扩展名 `.fen`。文件保存棋盘和行棋方，例如：

```text
rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w
```

小写为黑方、大写为红方；`w` 表示红方行棋、`b` 表示黑方行棋。马、象支持 `n/b` 和 `h/e` 两套符号。导入会校验布局、棋子及将帅，失败时保留原局面；成功后清空历史和重复计数，等待点击开始后按当前模式对弈。

FEN 不保存棋谱、剩余时间和认输/超时/协议和棋等终局原因。联机中可保存局面，打开文件需要先离开房间。

设置保存到应用配置目录的 `settings.json`，Windows 通常位于 `%APPDATA%\com.kikyoshaw.chinesechess\`。下次启动恢复对弈与显示偏好，联机需要重新建立连接。

## 工程结构

```text
src/
  App.vue                    主界面及操作流程
  components/                棋盘、棋谱、设置和联机窗口
  composables/useGame.ts      命令调用、事件、音效和倒计时
  types.ts                   前后端数据契约
src-tauri/src/
  lib.rs                     桌面命令及生命周期
  game/                      规则、中文记谱、FEN、终局和 AI
  session.rs                 对局状态、版本和后台任务
  network.rs                 TCP 握手、分帧及同步
  storage.rs                 设置及局面文件读写
public/assets/               棋盘、棋子、图标和音效
```

Rust 是棋局的唯一来源。前端操作携带棋局编号和版本；AI 在后台搜索独立棋局副本，新局、悔棋和读档会取消旧任务。联机校验连接代号及操作编号，防止过期或重复消息改变棋局。

## 手动验收

- 打开应用、新局或导入局面后等待超过一个步时，确认不计时、不允许落子、电脑不自动落子。
- 开始后等待数秒再暂停，确认余额冻结；继续后余额不补满，暂停前的旧 AI 搜索不会落子。
- 电脑先手也要等待开始；不限时模式同样受开始/暂停控制，终局后不能继续。
- 检查蹩马腿、塞象眼、炮架、兵过河、九宫、将帅照面、自将拒绝及解将。
- 检查将死、困毙、三次重复、认输、和棋和悔棋。
- 切换双方执子与先手；在 AI 思考时重开、悔棋或导入，观察旧走法是否被取消。
- 检查翻转和缩放后的点击位置、中文棋谱、音效及设置重启恢复。
- 设置短步时验证超时和换手重置；设为 0 验证不限时。
- 保存并重新打开 FEN；错误文件应提示并保留原局面。
- 用两个客户端检查同步、房主开始/暂停/继续、协商同意/拒绝、断线余额保留及重新加入；访客不能控制阶段，转本地后不自动恢复。
